# Разработка на Mac с M1

## Что можно делать локально

Исходники C++ и Cascades/QML можно редактировать на Mac. Для сборки QNX-бинарников
используется Linux-версия BlackBerry Native SDK внутри `linux/amd64` контейнера.
Docker на Apple silicon эмулирует x86-инструменты; выходные файлы при этом
предназначены для BB10 x86 или ARMv7, в зависимости от выбранной конфигурации.

Такой способ сборки описан автором [Term49C](https://github.com/jxw1102/Term49C#building-with-docker).
Для нашего проекта добавлены собственные скрипты, которые запускают qmake,
компилятор и упаковщик BAR. **29 октября 2026 года на этом M1 успешно собраны
оба BAR: x86 и ARMv7.** Архитектуры и содержимое пакетов дополнительно проверены;
результаты приведены в README и `build/verification.json`.

## Сборка

Нужен запущенный Docker Desktop для Apple silicon. На этом Mac он уже установлен.
Открыть терминал в каталоге проекта:

```sh
bash scripts/build-docker.sh simulator
bash scripts/build-docker.sh device
```

Выходные файлы:

- `build/simulator/berrygram-simulator.bar` — x86, для BB10 Device Simulator.
- `build/device/berrygram-device.bar` — ARMv7, для последующего тестирования
  на телефоне с подходящим способом установки development BAR.

При первом запуске Docker скачает community-образ SDK размером примерно
3 ГБ в сжатом виде; после распаковки потребуется больше места. Используется
`delaya73/bbndk`, зафиксированный по digest:

```text
sha256:26334b9fe9fe3e8d5984a814e2ebadbef94838994dbb768efd78f7b3da418bc4
```

Сам SDK остаётся историческим проприетарным SDK BlackBerry и используется
на условиях его лицензии. Это community-образ, а не новый официальный релиз.

Проект монтируется в контейнер для чтения, каталог `build` — для записи.
У работающего контейнера отключена сеть. Скачивание Docker-образа выполняется
до запуска контейнера. Упаковщик работает с временной копией файлов внутри
контейнера, поскольку он создаёт служебный файл `assets/.assets.index`.

## Проверка интерфейса

Сборка BAR и запуск интерфейса — отдельные задачи. Cascades предназначен для
QNX/BB10; обычный настольный Qt на macOS не исполняет этот интерфейс как
нативное Mac-приложение.

VMware Fusion на M1 не запускает x86-образ BB10. Но
[UTM/QEMU умеет эмулировать другую архитектуру](https://docs.getutm.app/settings-qemu/system/).
Найден [образ BB10 10.3.2 в QCOW2](https://archive.org/details/black-berry-10-simulator-bb-10-3-2),
который автор описывает как конвертированный для UTM. В архивных метаданных
указан размер 2 135 883 776 байт.

**29 октября запуск проверен на этом M1 в UTM 5.0.8.** Образ 10.3.2 доходит до
QNX и запуска служб, но останавливается на `START SERVICE: screen`.
Для контроля извлечён исходный VMware-образ 10.3.1.995 из уже загруженного SDK
и преобразован в QCOW2. Он останавливается на том же этапе, включая Safe Mode
с профилем Classic 720×720 и CPU Intel Nehalem.

Графический интерфейс BB10 не появился, установка BAR и работа приложения
в симуляторе не проверены. Это результат конкретных испытаний, а не доказательство
невозможности любого запуска BB10 через QEMU. Точная причина остановки пока
не установлена. [Конфигурации и результаты эксперимента](utm-experiment.md).

Практический следующий шаг — запуск исходного VMware-образа на имеющемся
Windows-ПК с Intel/AMD. Разработка и сборка обеих архитектур могут продолжаться
на M1; инструкции для переноса приведены в отчёте и [настройке Windows](windows-setup.md).

## Границы проверки

Для разработки Telegram-части переходить на Windows сейчас не нужно.
Добавленный процесс `berrygram-tdjson` проверен с настоящей TDLib на M1
без графического интерфейса и входа в аккаунт. [Команды и результаты](telegram-engine.md).
Для BB10 он компилируется обеими архитектурами, однако QNX-библиотека TDLib
пока отсутствует. Это отдельная задача переноса, которую Windows сама по себе
не решает.

Даже успешная компиляция обеих архитектур не подтверждает работу клавиатуры,
трекпада, Hub, уведомлений и фоновых режимов на настоящем Classic. Для этих
проверок позднее потребуется телефон. Telegram-движок также требует отдельного
переноса; текущий каркас использует демонстрационные данные.
