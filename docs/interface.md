# Интерфейс Berrygram 0.8.0

Нативный Cascades UI для Classic 720×720: светлая палитра, синий заголовок,
круглые аватары с инициалами, двухстрочный список чатов и пузырьки сообщений.
Компоновка и ввод проверяются на физическом Classic, включая собственные
снимки окна 720×720. Реальный вход в Telegram и отправка с аккаунта ещё не проверены.

## Изменения 0.8.0

- Компактный синий заголовок закреплён сверху. Меню открывается кнопкой с тремя
  точками; отдельная постоянная панель действий в переписке убрана.
- Поле ввода занимает оставшуюся ширину между скрепкой и кнопкой отправки.
  Оно растёт от одной до четырёх строк, затем прокручивается внутри. Enter
  привязан к отправке, Shift+Enter — к вставке новой строки в позиции курсора.
  Пустой ввод не вызывает отправку или ошибку. Действия вложений сохраняют
  прежние проверки доступа и записи голоса.
- Пузырьки стали компактнее, исходящие остаются справа. В личных чатах
  повторяющееся имя собеседника убрано. В группе имя появляется в начале
  блока сообщений одного автора. Блок разрывается при смене автора, даты,
  паузе более пяти минут и на границе непрочитанного.
- Дата вынесена в разделители «Сегодня», «Вчера» или календарную дату;
  возле сообщения остаются время и подтверждённый статус. Граница непрочитанного
  строится по `last_read_inbox_message_id` Telegram. В демо она синтетическая.
- Текст можно скопировать через контекстное меню пузырька. Системное меню
  получило отдельные значки документа, фото, голоса, истории и статусов.
- Строки списка чатов уменьшены, непрочитанные названия выделены жирнее;
  настройки подключения перенесены в дополнительное меню. Escape закрывает
  раскрытый поиск, S/U сохранены.

Разметку времени, дат и группировки формирует общий `MessagePresentation.hpp`
для реального хранилища и демонстрации. Это не изменяет обработку отправок,
неопределённых результатов и ручного восстановления вложений.

## Проверка нативного интерфейса

`scripts/check-classic-interface.py` выполняет действия в самом Cascades UI:
переход в демо, ввод текста, вызов привязок переноса/отправки, нажатие кнопки
отправки и кнопки меню, переходы назад и открытие группового чата. Поле ввода
проверяется на попадание в границы страницы при одной и четырёх строках.
13 ноября пользователь также подтвердил на физических клавишах Classic:
Shift+Enter вставляет новую строку, Enter отправляет сообщение.

`UiTools` включается для проверок только в development-сборке при наличии
`data/ui-check/enabled`. Запросы ограничены фиксированными действиями и
синтетической перепиской: при готовом настоящем аккаунте проверки запрещены.
Снимается только собственное окно приложения через Screen API. Проверки не
получают изображения чужих приложений или экрана входа. Дополнительное
разрешение захвата экрана не запрашивается. По завершении флаг удаляется и
таймер проверок отключается.

Локальные результаты: `build/ui-refresh/native-interface-checks.json`,
`build/ui-refresh/captures/`, `build/verification.json`. Старый экран для
сравнения загружается из сохранённой QML-разметки 0.7.1 с теми же демоданными.
Параметры API, реальные сообщения и другая пользовательская информация
не входят в эти снимки.

Значки — Google Material Design Icons, Apache 2.0. Лицензия, исходные URL,
хэши SVG и описание преобразования включены в `assets/licenses/` и BAR.

## Основные сценарии

- Первый запуск: «Начать общение» открывает вход. Демонстрация открывается
  отдельно через «Посмотреть интерфейс» и всегда подписана как демо.
- При открытии входа локальный движок запускается автоматически. Номер телефона
  и другие данные отправляются только после нажатия «Продолжить».
- Настройки API свёрнуты под «Свои параметры API». Версия TDLib и состояние
  сохранения сессии находятся в «Сведения о подключении».
- Список чатов показывает название, последнее сообщение, время и непрочитанные.
  Аватары пока состоят из инициалов: загрузка настоящих фотографий профиля ещё
  не реализована. Поиск открывается действием «Поиск», клавишей S или системным
  сочетанием. U открывает следующий непрочитанный чат.
- В переписке входящие и исходящие сообщения различаются выравниванием и цветом.
  Статус доставки остаётся текстовым, чтобы не выдавать ожидание за доставку.
  Enter отправляет текст, Shift+Enter переносит строку; системные переходы в начало/конец сохранены.
  Предыдущая история, отметка прочтения и очистка копий доступны в меню.
- Вложения, запись голоса, восстановление текста и черновиков сохраняют прежнюю
  логику. Реальную отправку и поведение этих элементов на Classic ещё нужно проверить.

## Подключение без регистрации собственной пары для теста

`api_id/api_hash` идентифицируют приложение, а не пользователя аккаунта.
Для готового клиента достаточно одной пары, зарегистрированной разработчиком
Berrygram: пользователи затем входят по номеру/коду. Сейчас такой пары у проекта нет.
QR-вход тоже требует параметров приложения и пока не реализован.

В `Device-Debug` / `Simulator-Debug` включена кнопка «Тестовое подключение».
Она использует [официальные TEST ONLY credentials Telegram Desktop](https://github.com/telegramdesktop/tdesktop/blob/dev/docs/api_credentials.md).
Telegram разрешает их для тестирования, сильно ограничивает на сервере и требует
собственную пару перед распространением приложения. Успешный вход не гарантирован.
Это не режим тестовых дата-центров: `use_test_dc` остаётся `false`.

Выбор выполняется явно; тестовая пара не записывается в `api.json` и при следующем
запуске не выбирается автоматически. `BERRYGRAM_DEVELOPMENT_TEST_API` определяется
в qmake только для debug. В release метод возвращает `false`, кнопка скрыта.
Отдельный тест сборки без этого определения подтвердил отключение.
Существующие собственные сохранённые параметры тестовая кнопка не перезаписывает.

Официальные источники:
[получение API-параметров](https://core.telegram.org/api/obtaining_api_id),
[начальная настройка TDLib](https://core.telegram.org/tdlib/getting-started),
[QR-вход](https://core.telegram.org/api/qr-login).

## Состав и проверки

`assets/Ui.js`, `AppHeader.qml`, `Avatar.qml` и `ChatRow.qml` задают общий стиль.
Фоны в `assets/ui/` — простые элементы интерфейса, а не изображения переписки.
Пересоздать их на Mac: `swift scripts/generate-ui-assets.swift assets/ui`.
Метаданные `.amd` сохраняют скругления пузырьков при масштабировании.

Проверены 46 Qt-строк (включая setup/cleanup), debug/release-поведение тестового
подключения, компиляция обеих BB10 целей, содержимое QML/JS/PNG/AMD в BAR.
Результаты — `build/ui-design/` и `build/verification.json`.
Вход с реальным аккаунтом не выполнен. Версия 0.7.1.9 установлена на Classic,
хэши всех упакованных native-файлов (включая QML и фоны) сверены с BAR.
Пользователь подтвердил новый первый экран, список с аватарами и пузырьки в демо,
но заметил ошибку: исходящие оставались слева. В 0.7.1 строка сообщения занимает
измеренную ширину ListView, а DockLayout прижимает пузырёк к нужному краю.
Пользователь подтвердил исправление в демо на Classic: свои сообщения справа,
входящие слева. Настоящая переписка пока не проверена.
Автоматический снимок экрана не получен:
системный Screen API отклонил контекст захвата; этот механизм защиты не менялся.
