# Telegram 0.17.0.23: вход и широкие сообщения

## Сообщения

В группах, супергруппах, каналах и обсуждениях карточки сообщений занимают
доступную ширину экрана с небольшими боковыми отступами. Ширина текста,
цитат, реакций и фотографий рассчитывается от ширины строки списка.
Личные диалоги сохраняют отдельные входящие и исходящие пузырьки.

Для широких карточек добавлен режим `EmojiView.fillWidth`. Одного изменения
ширины фона недостаточно: составной текстовый компонент мог выбирать ширину
по промежуточной оценке длины текста. Теперь обычный абзац получает заданную
ширину до измерения высоты и переносится у правого края карточки. Вариант
с emoji также использует полную ширину для размещения слов и изображений.
Исходные абзацы и форматирование Telegram сохраняются.

## Вход

Белые формы с иллюстрациями телефона, письма и пароля адаптированы к экрану
Classic 720×720. Использованы уже поставляемые изображения Twemoji с существующей
атрибуцией. Стартовый экран содержит логотип Telegram и кнопку «Начать общение».
Форма телефона содержит страну, редактируемый международный код и номер.
Самодельной цифровой клавиатуры нет; используется ввод Classic.

При сохранённом входе приложение восстанавливает подключение и показывает чаты.
Промежуточного выбора демо, подключения и отдельной кнопки открытия чатов нет.
Проверка маршрутов учитывает сохранённое подключение, первый вход, ожидание
ответа, пароль и переход в основное приложение после авторизации.

Development-сборка сохраняет только имя выбранного тестового профиля в закрытом
`connection.json`; сами тестовые ключи в него не записываются. Release-сборка
игнорирует этот профиль. Собственные параметры приложения сохраняются через
прежний защищённый механизм `api.json`. В этой конкретной установке перенесён
ранее выбранный тестовый профиль; приложение не определяет API по наличию базы.
Подробности: [авторизация](telegram-login.md).

## Проверка

В Linux ARM64 / Qt 5 прошли 114 проверок, включая восстановление выбранного
профиля и различение личных диалогов, групп и каналов. Отдельно проверена
сборка без development API: сохранённый тестовый профиль не включает тестовые
ключи. `node tests/auth-routing-tests.js` проверяет функции маршрутизации из
исходного QML, включая отсутствие действий с аккаунтом в режиме просмотра.

Сценарий `scripts/check-classic-auth-layout.py` проверяет нативные экраны на
Classic с демонстрационными данными. Формы телефона, кода и пароля имеют отдельный
режим просмотра, который не отправляет запросы входа. Снимки делаются после
стабилизации перехода между экранами. После проверки восстанавливается рабочая
сессия и отключается проверочный опрос.

На Classic ширина карточек групп и каналов составила 707,2 пикселя при ширине
списка 720 пикселей. После исправления компонента текста обычные предложения
занимают доступную ширину, а личные сообщения сохраняют пузырьки меньшего размера.
При холодном запуске проверочный запрос подтвердил состояние `ready` без
выбора подключения. После просмотра экранов рабочая сессия восстановлена.

Автоматический снимок формы пароля возвращал предыдущий кадр приветствия,
несмотря на подтверждённое состояние страницы `password`. Поэтому такой снимок
не используется как доказательство визуального соответствия экрана пароля.
Формы телефона и кода, приветствие и переписка проверены по нативным снимкам.
