# Telegram 0.17.1.24: восстановление запуска

После нативной проверки 0.17.0.23 на телефоне остался служебно запущенный экземпляр
приложения с работающим TDLib. При открытии обычным значком запустился второй
экземпляр. На устройстве одновременно наблюдались два интерфейсных процесса и
два процесса движка, использующих один каталог аккаунта. После корректного
закрытия обоих процессов пользователь подтвердил нормальный запуск значком.
База, ключ шифрования и сохранённый профиль подключения не изменялись.

В 0.17.0.23 ошибка восстановления параметров могла оставлять фазу `parameters`
без активного запроса. Стартовый экран продолжал показывать «Открываем ваши чаты…»
и скрывал ошибку. В 0.17.1.24 ошибка завершает состояние загрузки, показывается
без необработанных диагностических данных и доступна кнопка повторного подключения.
Отсутствующий движок также не считается продолжающимся восстановлением.
Сообщение о занятой базе определяется по ограниченным признакам ошибки блокировки;
путь к файлам аккаунта в интерфейс не передаётся.

Сценарий `check-classic-auth-layout.py` теперь завершает служебный экземпляр
перед передачей телефона пользователю. Проверку запуска после установки нужно
проводить обычным значком телефона. Запуск через служебный launcher не заменяет
такую проверку и не должен оставаться активным параллельно с обычным запуском.

Добавлены проверки ошибки блокировки, сохранности ключа и возможности повторить
подключение. Проверки маршрутизации также подтверждают, что ошибка восстановления
и отсутствие движка не оставляют стартовый экран в состоянии загрузки.

Проверка 0.17.1.24: 115 проверок Qt прошли; обе сборки BAR проверены по составу,
архитектуре и ресурсам. Проверки QML-маршрутизации подтвердили выход из состояния
загрузки при ошибке и отсутствии движка. На телефон установлены и проверены все
97 файлов пакета с сохранением данных. Служебный запуск после установки не выполняется.
