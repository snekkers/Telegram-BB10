# Первый запуск на Classic

12 ноября 2026, Mac M1 / macOS 27.0.1, физический BlackBerry Classic SQC100-4.
Идентификаторы PIN, IMEI и серийный номер в этот документ не включены.

## Подтверждено

- Телефон определён по USB и `discovery.cgi`: SQC100-4, исходная BB10 10.3.3.2049.
- Пользователь разрешил полную очистку телефона и подтвердил отсутствие пароля
  блокировки перед работой с загрузчиком.
- Из предоставленного архива `z30_q20_root-v4.7z` извлечены ОС с AutoRoot V4
  и соответствующий радиомодуль 10.3.3.3216. Образы сверены с вложенными данными
  EXE, проверены CRC32 и SHA-256.
- Неизменённый RAM-loader `loader_9400270A-00.bin` из CAP назначен под ID
  `9700270A` телефона. Реальный SQC100-4 принял его; аппаратные сведения и
  таблица разделов прочитаны до записи образов.
- Первая запись остановилась на 21% с `USB write error (-1)`. После обновления
  libusb с 1.0.28 до 1.0.30 и принудительного перезапуска выполнена полная
  запись ОС и radio: обе операции достигли 100%, `Send signature`, `Done`.
  Ошибка `LIBUSB_ERROR_OTHER` возникла уже при переподключении после перезагрузки;
  результат затем проверен независимо через работающую BB10.
- `discovery.cgi` подтвердил BB10 10.3.3.3216. Root проверен созданием временного
  файла через SFTP с фактическим владельцем UID 0; временный файл удалён.
- Установлен V4 update 1 с сайта автора. Содержимое двух обновлённых файлов
  сверено с исходным пакетом до и после контрольной перезагрузки. После неё
  доступ с UID 0 сохранился.
- Общий ключ авторизации и общий ключ SSH-сервера заменены индивидуальными.
  Новый вход и новый ключ сервера проверены; ключи сохраняются вне `build/`.
- `berrygram-device.bar` 0.6.0.6 установлен системным installer: `progress::100`,
  `result::success`. Каталог приложения:
  `/apps/org.example.berrygram.testDev_e_berrygramc6c1ba5f`.
- Пользователь подтвердил, что Berrygram открылся и показывает ввод API ID/hash.
  Это подтверждение пользователя, автоматического снимка экрана телефона нет.

## Исправление ARM-движка в 0.6.1

Первый диагностический запуск загрузил TDLib 1.8.69, но JSON-запросы возвращали
`Unexpected string end`. Причина найдена в приватном overlay `string.h`:
GNU `<cstring>` повторно создавал рекурсивные inline wrappers, из-за которых
Clang неверно оптимизировал JSON-парсер. Добавлен макрос правильных ISO C++
перегрузок; TDLib целиком пересобрана. Подробности — в [описании порта](qnx-port.md).

На этом же Classic под `devuser` прошли изолированные проверки без аккаунта:

- C++17 optional, atomic, mutex, thread и вызовы const/mutable `memchr`/`strchr`.
- OpenSSL: источник энтропии, SHA-256 и создание TLS context.
- Полный процесс `berrygram-tdjson`: версия 1.8.69, JSON, переданный частями,
  русский текст и эмодзи, правильные UTF-16 offsets URL, начальное состояние
  авторизации и штатное закрытие с кодом 0. Stderr пуст.

Отчёт `build/porting/device-tests.json` содержит хэши всех шести проверенных ELF.
Упаковщик принимает его только при полном совпадении хэшей и трёх успешных
сценариев. Отдельно проверено, что несовпадающий отчёт отклоняется до изменения
комплекта. SHA-256 исправленной `libtdjson.so`:
`6f6ba871edcd98a8e59b9572f9e2028a3c39821b6e70524daa1a4ae7a0895bcb`.

На Mac/Linux прошли 45 Qt-строк тестов (включая setup/cleanup), три сценария
локального стенда и проверка состава обоих BAR 0.6.1.7.

Обновление 0.6.1.7 установлено поверх 0.6.0.6 без удаления данных приложения:
installer подтвердил `progress::100` и `result::success`. Версия в установленном
manifest и SHA-256 всех файлов `native/berrygram` / `native/telegram/` сверены
с проверенным BAR. Через launcher PPS запущен процесс новой версии; `pidin`
подтвердил правильный application ID. Визуальный запуск и строка версии TDLib
в интерфейсе ещё требуют отдельного подтверждения пользователя.

## Что ещё требует проверки

Вход в настоящий аккаунт, чаты, отправка, TLS, медиа, клавиатура, трекпад,
возобновление соединения и работа в фоне на Classic ещё не проверены.

На штатной оболочке не нашлись утилиты `id` и `printf`; для проверки root
использовался владелец созданного файла. `run-probe.sh` передаёт JSON через heredoc.

## Локальные инструменты и отчёты

Подготовка и журналы находятся в игнорируемом `build/root-preparation/`:

- `installation-result.json` — итоговая фиксация установки и подтверждения запуска.
- `image-verification.json` — хэши и результаты проверки образов.
- `flash-recovery.log` — полная запись ОС и radio с libusb 1.0.30.
- `berrygram-install.json` — результат установки BAR.
- `ssh-classic.py` — локальный клиент Paramiko 3.5.1 для старого SSH в BB10.

Индивидуальные ключи и метаданные устройства находятся в
`~/Library/Application Support/Berrygram Devices/Classic SQC100-4/`.
Приватные ключи имеют права 0600, каталог — 0700. В репозиторий их не добавлять.
Рабочий USB-адрес после запуска AutoRoot: `169.254.0.1`, адрес Mac: `169.254.0.2`.

Встроенный OpenSSH 10.3 на этом Mac закрывал соединение с SSH 6.2 телефона;
проверка выполнена через отдельный Paramiko с закреплённым ключом сервера.
Совместимость SHA-1 включена только для этого локального соединения.
