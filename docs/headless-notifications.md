# Уведомления Berrygram после закрытия

В текущей версии уведомления зависят от работающего процесса приложения. Сворачивание и полное закрытие — разные состояния: после полного закрытия получение сообщений не гарантируется.

BB10 поддерживает отдельные headless-службы. Для постоянно работающей службы в режиме выпуска документация SDK указывает специальное разрешение `_sys_headless_nostop` и подписанный пакет; в режиме Device-Debug предусмотрена отдельная возможность проверки. Установленная здесь сборка разработческая. Наличие этой возможности для конкретной установки и жизненный цикл службы после закрытия, перезагрузки и при ограничениях системы ещё нужно проверить на телефоне. Источник: [примечания к выпуску BlackBerry Native SDK](https://docs.waitberry.com/native/downloads/releasenotes.html).

Практический вариант: отдельная служба становится единственным владельцем движка Telegram и базы, принимает обновления и передаёт интерфейсу состояние по локальному защищённому каналу. При выходе из интерфейса служба продолжает работу, а при его открытии интерфейс подключается к ней. Два одновременно запущенных экземпляра TDLib не должны использовать одну базу. Альтернативный вариант с передачей владения при переходе в фон сложнее из-за возможных пропусков, гонок и времени запуска.

До включения функции нужны отдельный прототип жизненного цикла службы, тесты повторного подключения и доставки уведомлений, проверка безопасности учётной записи и измерение потребления аккумулятора на реальном устройстве. Часовое измерение батареи пользователь отложил; данных о расходе пока нет.

Телефон содержит `librdaOpus.so.1` с экспортируемыми функциями декодирования Opus. Это позволяет исследовать локальный декодер для голосовых, но не доказывает, что системный проигрыватель поддерживает файлы Telegram; совместимость и производительность нужно проверить на реальных файлах.
