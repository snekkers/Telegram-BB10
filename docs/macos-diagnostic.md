# Сетевой стенд на Mac M1 — 0.4.0

Стенд позволяет проверить авторизацию и переписку без BB10 GUI. Локальная
страница управляет нативным процессом Qt Core, который использует те же
`TelegramSession`, `TelegramStore` и `JsonCodec`, что BB10-приложение.
Для QNX JSON обрабатывается через `JsonDataAccess`, для Mac — через Qt 5.
Внешний сервер для аккаунта не нужен: TDLib работает на этом Mac.

## Запуск уже подготовленного стенда

Для просмотра интерфейса без аккаунта и без ключей:

```sh
bash scripts/run-macos-demo.sh
```

Демо использует тестовый процесс, автоматически показывает вымышленные чаты
и заметно подписано. Соединения с Telegram нет. Его адрес сохраняется отдельно
в `build/macos-development/demo-url.txt`.

Для настоящей TDLib и своего аккаунта:

```sh
bash scripts/run-macos-diagnostic.sh
```

Скрипт выводит адрес `http://127.0.0.1:PORT/#...`. Откройте его целиком:
фрагмент после `#` содержит ключ доступа к локальному интерфейсу.
Адрес также записывается в `build/macos-development/diagnostic-url.txt`
с правами 0600. Он действителен, пока работает процесс стенда.
Для завершения всего стенда нажмите Ctrl+C в терминале запуска.
Кнопка «Остановить движок» закрывает TDLib, сохраняя сессию.

1. Нажмите «Запустить движок».
2. Введите собственные API ID и API hash. Их получают через
   [my.telegram.org/apps](https://my.telegram.org/apps): после входа нужно
   создать приложение в API development tools. Без этих параметров проверяется
   только запуск TDLib. При временном ограничении Telegram получение параметров
   и вход следует отложить; код приложения и тестовый процесс продолжают работать.
3. По желанию оставьте сохранение параметров API включённым.
4. Пройдите шаги, которые запросит Telegram: номер, код, пароль или почта.
5. После входа выберите чат. Поиск фильтрует уже загруженные чаты.
6. Enter отправляет текст, Shift+Enter добавляет строку, ⌘F открывает поиск.
   «Непрочитанные» переключает переписку, «Ранее» загружает историю.
7. «Прочитано» явно отмечает историю до последнего загруженного сообщения.
8. Фото и документы загружаются по кнопке. Фото можно показать в странице,
   документ — сохранить обычной загрузкой браузера. Размер ограничен 50 МБ.

Отправка происходит только по действию пользователя. Тесты не отправляют
настоящие сообщения. При неопределённом результате приложение не повторяет
`sendMessage` автоматически.

## Данные и границы доступа

- По умолчанию данные находятся в
  `~/Library/Application Support/Berrygram Diagnostic`.
  Для изолированного набора данных используйте `--data /absolute/path`.
- Каталог создаётся с правами 0700. API-параметры сохраняются в `api.json`
  с правами 0600, без дополнительного шифрования этого файла. Удалить их можно
  отдельной кнопкой; сохранённая сессия TDLib при этом остаётся.
- Коды и пароль двухэтапной проверки не сохраняются в настройках и не
  выводятся в журналы. API hash не включается в снимки состояния интерфейса.
- База TDLib получает случайный 32-байтный ключ. Файл `database.key` хранится
  рядом с базой с правами 0600. Дисковый кеш сообщений включён.
  После авторизации ранее загруженная история может читаться из базы;
  при `connectionStateWaitingForNetwork` запросы истории используют `only_local`.
- Черновики сохраняются через `setChatDraftMessage`. Они поступают в базу
  TDLib и могут синхронизироваться Telegram между устройствами.
  Изменения отправляются после короткой паузы и при смене чата/закрытии.
  При аварийном завершении последние ещё не обработанные изменения могут потеряться.
- HTTP-сервер слушает только `127.0.0.1`. API требует случайный ключ,
  проверяет Host и Origin, ограничивает тело запроса. Ключ интерфейса остаётся
  в sessionStorage текущей вкладки, чтобы перезагрузка страницы работала.
- Перед отправкой и сохранением черновика дополнительно проверяется ID чата:
  запоздалая команда из старой переписки отклоняется.
- Сервер отдаёт вложения только из каталога TDLib `files`, для сообщений
  текущего чата. Символьные ссылки и выход за этот каталог отклоняются.
  Входящие запросы и содержимое переписки не журналируются.

## Сборка из исходников

Нужны Xcode Command Line Tools, Python 3, Perl, make и Docker для PHP-шага
разбиения исходников TDLib. Всё устанавливается в игнорируемый `build/`;
системный Qt и Homebrew не требуются.

```sh
python3 scripts/prepare-macos-development.py
python3 -m pip install --require-hashes --target build/tools/cmake-native -r porting/requirements-macos.txt
docker build --platform linux/amd64 -t berrygram/porting:bookworm porting
bash scripts/build-macos-development.sh dependencies
bash scripts/build-macos-development.sh qt
bash scripts/build-macos-development.sh tdlib
bash scripts/build-macos-diagnostic.sh
python3 tests/diagnostic-integration.py
python3 scripts/verify-macos-development.py
```

Собраны и проверены на macOS ARM64:

- TDLib 1.8.69, исходники `4c6377aa7386c39217878a9a56d581922ad37ca4`.
- OpenSSL 3.5.9 и zlib 1.3.2, статически включённые в TDLib.
- Qt Core 5.15.19 для диагностического процесса.

Архивы проверяются по SHA-256. Mac-исходники извлекаются отдельно от QNX-порта.
Официальный `SplitSource.php` используется с фиксированным seed 0.
Mac-библиотека зависит только от системных libc++ и libSystem; community
библиотеки OpenSSL 1.1 из раннего smoke-теста для входа не используются.
Qt 5 используется только на Mac; в телефонном BAR остаётся системный Qt 4.

Отчёты: `build/macos-development/verification.json`, `diagnostic-tests.json`.
Qt-тесты общего кода: `build/session-tests/results.xml` и `store/results.xml`.

## Что подтверждено

Нативный диагностический процесс на M1 проверен с локально собранной TDLib:
версия, начальное состояние и закрытие, включая EOF при активном дочернем
процессе. Номер и параметры аккаунта в этом тесте не передаются.

Интеграция HTTP → нативный Qt → тестовый процесс проверяет шаги авторизации,
чаты, сообщения, черновики, сохранение API, загрузку вложения и ограничения
доступа. В браузере проверены ввод, клавиатурная отправка, смена чатов,
восстановление черновика, просмотр тестового изображения и перезагрузка.
Тестовый режим подписан заметной плашкой и не связывается с Telegram.

**Настоящий вход, реальная переписка, сохранение истории/черновиков аккаунта
после перезапуска и работа на BB10 ещё требуют проверки с устройством/аккаунтом.**
Успех локальных тестов этого не подтверждает.

## Изменения BB10-интерфейса

- Сохранение API-параметров и повторное использование сохранённой пары.
- Черновики, поиск среди загруженных чатов, переход к следующему непрочитанному.
- `S` в списке открывает поиск, `U` — непрочитанный чат, когда поле поиска
  не в фокусе. В переписке `Alt+U` переключает следующий непрочитанный;
  `R` запрашивает более раннюю историю, когда поле сообщения не в фокусе.
- Системные команды перехода в начало/конец списка и возврат фокуса к вводу.
- Фото до 1280×1280 отображаются в сообщении после загрузки. Документы
  передаются системному обработчику как копия только для чтения.
- Прочтение отмечается явным действием, без предположений о видимой области.

Это скомпилировано для BB10; раскладка, клавиши, трекпад, отображение фото
и системный просмотр файлов ещё не проверены на Classic/симуляторе.
Отправка вложений, запись и воспроизведение голосовых сообщений остаются
следующим этапом.
