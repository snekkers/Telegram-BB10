# Сохранение отправок и очистка — 0.6.0

Выбранное вложение и подпись сохраняются до отправки. При возвращении в чат,
перезагрузке страницы или перезапуске приложения готовая копия восстанавливается.
На Mac выбор файла сразу копирует его на локальный стенд; отправка в Telegram
происходит отдельной кнопкой. Запись голоса сохраняется после завершения записи.

Общий `LocalOutbox` используется на Mac и BB10. Журнал `outbox.json` находится
в каталоге данных приложения, рядом с `uploads`. Он записывается через временный
файл, `fsync` и атомарное переименование. Права файла — 0600, каталога — 0700.
Журнал содержит текст незавершённых отправок, подписи и относительные пути;
дополнительного шифрования журнала и копий вложений нет.

## Жизненный цикл

| Состояние | Что означает | Что происходит после перезапуска |
| --- | --- | --- |
| `draft` | Копия подготовлена, кнопка отправки ещё не нажата | Файл и подпись возвращаются в поле ввода |
| `submitting` | Намерение записано до передачи запроса движку | Результат считается неизвестным |
| `pending` | TDLib приняла запрос, окончательного результата ещё нет | Результат считается неизвестным; выполняется запрос известного сообщения |
| `uncertain` | Нет достоверного результата | Показана просьба проверить историю перед ручным повтором |
| `failed` | Получен явный отказ | Можно восстановить текст или вложение вручную |
| `sent` | Получено подтверждение успешной отправки | Старую копию можно очистить через сутки |

Чтение журнала не вызывает `sendMessage`. TDLib может продолжить уже принятую
ею отправку; приложение не создаёт повторный запрос само. Кнопка подготовки
повтора возвращает файл в поле ввода. Отправка требует отдельного нажатия.
Каждая новая попытка получает собственную запись: поздний ответ на прежнюю
попытку не должен менять новую. Исходная неопределённая попытка продолжает
защищать свой файл от очистки.

Перед восстановлением определяется собственный пользователь через `getMe`.
Черновики и записи фильтруются по аккаунту и чату. Если доступны ID незавершённых
сообщений, их состояние запрашивается через `getMessage`; ошибка или отсутствие
сообщения сохраняют неопределённость. При большом числе записей часть остаётся
для ручной проверки, чтобы запуск списка чатов не упирался в лимит запросов.

Текст в поле ввода также сохраняется локально перед передачей черновика TDLib.
На Mac изменения обрабатываются после паузы около 350 мс, на BB10 — около
600 мс; при смене чата и штатном закрытии выполняется сохранение.
Последние изменения до окончания этой паузы при аварийном завершении могут
не сохраниться. Локальный неподтверждённый черновик имеет приоритет при
восстановлении; после принятия TDLib локальная запись черновика удаляется.

## Очистка

Автоматическая проверка запускается после определения аккаунта, примерно раз
в минуту и перед подготовкой нового файла. Доступна кнопка «Очистить старые
копии». Удаляется только собственная копия, чья отправка подтверждена более
суток назад. Действующие черновики, активные отправки, явные отказы и
неопределённые попытки сохраняются. Общий файл нескольких попыток защищён,
пока хотя бы одна из них не имеет подтверждения.

Оригинал, выбранный пользователем, не удаляется. Кеш скачанных вложений TDLib
`files` эта очистка не изменяет. Неизвестные файлы, включая оставшиеся от 0.5.0,
автоматически не удаляются: для них нет надёжного подтверждения завершения.
При достижении лимита копий может понадобиться ручная проверка таких файлов
после остановки движка. Ограничения — 32 копии / до 256 МиБ на Mac;
на BB10 сохраняется резерв под следующую копию до 50 МиБ.

Повреждение журнала, символьная ссылка вместо журнала или ошибка его записи
блокируют новые отправки, требующие сохранения. Неизвестные файлы остаются
на месте; журнал не обнуляется автоматически. Копии без доступного журнала
нужно сохранить до ручного восстановления данных.

## Проверки

Общие Qt-тесты включают восстановление после создания нового процесса,
привязку к аккаунту, права файлов, повреждённый журнал, отказ записи до
передачи движку, очистку старых подтверждённых копий и защиту общих файлов.
Подставной процесс проверяет потерю сети, тайм-аут, поздний ответ и завершение
движка без повторного `sendMessage`.

На M1 дополнительно проверены полный перезапуск нативного клиента/HTTP-сервера,
сохранение ID выбранного файла и принудительный `SIGKILL` после передачи запроса.
После нового запуска файл сохранился, результат остался неопределённым,
новый запрос отправки не появился. В браузере проверены смена чата,
перезагрузка и восстановление выбранного документа с подписью после перезапуска.

Отчёты: `build/verification.json`, `build/macos-development/diagnostic-tests.json`
и `build/macos-development/verification.json`.

Это локальные проверки с подставными событиями/процессом. Работа очереди с
настоящим аккаунтом Telegram, микрофон и выполнение на Classic ещё не проверены.
Обе BAR-сборки компилируются штатным SDK с Qt 4/C++98.
